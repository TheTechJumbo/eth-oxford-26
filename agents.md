You are building a hackathon project called SkillStake. SkillStake is a skill-based 1v1 esports challenge dApp, not a gambling platform. Two players agree to a challenge, stake funds, play a real match, and the winner receives the combined stake instantly once the result is verified. There are no odds, no house, no randomness introduced by the platform, and no expectation of profit beyond winning a skill-based match. The project is framed as competitive escrow and settlement infrastructure, not betting.

The initial game target is Apex Legends. The default win condition is MOST_KILLS, but the system supports other conditions such as PLACEMENT and POINTS. Players agree on a match reference string. Funds are escrowed in a smart contract. An off-chain referee service verifies match results and submits a signed result to the smart contract, which then settles the payout.

The system is built to showcase Flare as the execution and settlement layer, using the Flare Costón2 testnet with chainId 114. Local development uses Anvil with chainId 31337. The staking currency is the native token, meaning ETH on Anvil and C2FLR on Costón2. No ERC20 tokens are used for staking.

The tech stack consists of Solidity smart contracts built with Foundry, a Node.js and TypeScript referee service using Express, and a Next.js frontend using TypeScript, Tailwind, wagmi, RainbowKit, and viem. The frontend includes a results table and a network guard that prompts users to switch to Flare Costón2 when on the wrong chain.

The SkillStake smart contract includes a challenge lifecycle with states OPEN, FUNDED, RESULT_SUBMITTED, SETTLED, and REFUNDED. A Challenge struct stores playerA, playerB, stakeWei, winCondition, expiry timestamp, matchRef, status, winner, scoreA, and scoreB. Functions include createChallenge, joinChallenge, submitResult with EIP-712 signature verification, settle, and refundIfExpired. Security features include a reentrancy guard, checks-effects-interactions, and prevention of double settlement or refund. The contract emits events for challenge creation, joining, result submission, settlement, and refunds.

The referee service signs match results using EIP-712 typed data. The domain uses name SkillStake, version 1, the active chainId, and the deployed SkillStake contract address. The signed message includes challengeId, matchRef, playerA, playerB, winCondition, scoreA, scoreB, winner, and timestamp. The referee service reads the challenge from the chain, fetches Apex match stats using the Tracker Network API, computes scores and the winner, signs the payload with REFEREE_PRIVATE_KEY, and submits the result on-chain. If the external API fails, a deterministic demo fallback is used. The referee service logs network configuration on startup and fails hard if the configured chainId does not match the provider network.

Deployment is handled via a Foundry deploy script. The script reads environment variables PRIVATE_KEY for the deployer, REFEREE_ADDRESS for the referee signer public address, NETWORK to select local or coston2 mode, RPC_URL, and EXPLORER_URL. After deployment, the script writes a JSON file to contracts/deployments/latest.json containing the network name, chainId, rpcUrl, explorer URL, SkillStake contract address, referee signer address, deployer address, and deployed block number. This JSON file is used as a shared configuration source for both the frontend and the referee service.

There is a one-click development script called ./dev and a Makefile target make dev. When NETWORK is set to local, ./dev starts Anvil, deploys the contracts, seeds demo wallets with native ETH, and starts the referee service and frontend. When NETWORK is set to coston2, ./dev deploys to Flare Costón2, writes the deployments JSON, checks C2FLR balances, and starts the referee service and frontend without starting Anvil. The directory contracts/deployments must exist before deployment or vm.writeJson will revert.

A seed script is used to fund demo wallets locally or to check balances and print faucet instructions on Costón2. The faucet for Costón2 is [https://faucet.flare.network/coston2](https://faucet.flare.network/coston2). The frontend shows a switch-network button and displays results including challenge ID, players, stake, win condition, status, scores, winner, result submission timestamp derived from the ResultSubmitted block timestamp, and the settlement transaction hash from the Settled event.

Smart contract tests are written using forge-std. Foundry and forge-std are installed correctly. The tests testCreateJoinSubmitSettle and testRefundIfExpired both pass successfully, confirming correct behavior of challenge creation, joining, result submission, settlement, and refunds.

The current blocker encountered was a deployment error caused by vm.writeJson failing because the deployments directory did not exist, which was fixed by creating the directory. The next blocker was a missing REFEREE_ADDRESS environment variable, which is required by the deploy script to set the authorized referee signer. The correct fix is to export REFEREE_ADDRESS to the public address corresponding to REFEREE_PRIVATE_KEY before running the deploy script or ./dev. After setting PRIVATE_KEY, REFEREE_PRIVATE_KEY, and REFEREE_ADDRESS, the system should deploy and run successfully locally and on Flare Costón2.
